# KVSSD Attention v0.2.0 release notes (release-gated draft)

Version 0.2 evolves the original NVIDIA CUDA vertical slice into a backend-oriented system with a
portable fused kernel, tiered storage selection, and a real serving-runtime integration boundary.
These notes remain a draft until the hardware qualification table is complete.

## Portable fused attention

The Triton backend consumes packed INT2/INT4 keys and values plus FP16 group scales directly. It
performs low-bit unpacking, dequantization, GQA mapping, score accumulation, online softmax, and value
accumulation in one kernel without materializing an FP16 KV cache. The same source targets NVIDIA
CUDA and AMD ROCm.

Backend selection is explicit and observable. `auto` prefers the hand-written CUDA extension, then
Triton, then the reference implementation. Naming an unavailable backend raises a diagnostic instead
of silently benchmarking a fallback.

## GDS-capable storage

The optional `kvssd._gds` extension owns cuFile driver/file-handle lifetime and reads complete aligned
records into aligned CUDA allocations. The bounded loader overlaps independent synchronous cuFile
reads across workers, and fused attention consumes GPU payload views after a stream-safe coalescing
step. Automatic storage selection falls through to Linux `O_DIRECT` and buffered `preadv`.

The existing on-disk format remains version 1 and requires no migration.

## vLLM proof of concept

`KVSSDOffloadingSpec` uses vLLM 0.25's public V1 tiering API. Its secondary tier maps content hashes
and cache-group IDs to CRC-protected, 4 KiB-aligned INT2/INT4 records and implements asynchronous
lookup, store, and reload lifecycle hooks. Configuration fingerprints isolate model, dtype, cache
layout, quantization, and parallelism.

vLLM 0.25 requires every secondary tier to stage through its CPU primary tier. Consequently this
adapter proves persistent packed prefix reuse but does not claim direct GDS-to-PagedAttention.

## Compatibility

- Python 3.10+
- PyTorch 2.4+
- Triton 3.2+ on Linux (optional)
- vLLM 0.25.x on Linux (optional)
- CUDA 12.2+/GDS development files for the optional cuFile extension
- Original version-1 KVSSD stores

## Qualification table

| Path | Status before release | Evidence required |
|---|---|---|
| Portable CPU/reference | Passed | Linux and Windows test suites |
| Linux `O_DIRECT` | Passed | Aligned native-filesystem read and CRC decode |
| Triton interpreter | Passed | INT2/INT4 semantic matrix and chunk merge |
| vLLM 0.25 contract | Passed | Tagged-source gate and fake lifecycle test |
| NVIDIA Triton/CUDA | Pending | Opt-in numerical hardware job |
| NVIDIA GDS | Pending | Direct CUDA record read with CRC equality |
| AMD Triton/ROCm | Pending | Opt-in numerical hardware job |

No throughput number belongs in the final release notes unless its raw benchmark JSON is attached and
the selected backend, GPU, SSD, filesystem, software stack, cache state, and workload shape are named.
